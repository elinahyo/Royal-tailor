## 반영한 범위

| 흐름 | 포함 화면 |
|---|---|
| 첫 실행 | 타이틀, 게스트 진입, 개인정보·광고 설정, 선택 로그인 |
| 독립 튜토리얼 | 이동→집기→재단→봉제→납품, 완료·건너뛰기·일시정지 |
| 에피소드·맵 | 5개 에피소드, 각 12맵, 잠금·해금·최고 별, 첫 맵과 다음 에피소드 진입 |
| 주문 준비 | 목표·시간·별 기준, 보유 아이템, 코인 구매, 잔액 부족, 광고 획득 |
| 플레이 | 주문·타이머·점수 HUD, 조이스틱·상황별 행동, 재단·봉제·납품, 조건부 장식 |
| 플레이 예외 | 잘못된 재료·납품, 작업대 이탈, 주문 변경, 근위병 이동 예고, 10초 경고 |
| 중단·실패 | 일시정지, 재시작·나가기 확인, 시간 초과, 40초 연장, 연장 사용 완료, 실패 |
| 결과·회복 | 1~5성, 최고 기록 갱신, 재도전, 광고 보너스, 하트 0·회복 |
| 서비스 예외 | 광고 없음·중단·한도·지급 확인, 오프라인, 저장 실패, 비정상 종료 복귀 |
| 설정·계정 | 음악·효과음·진동·효과 감소, 도감, 백업 권유, 로그인 성공·실패, 기록 충돌, 로그아웃·삭제 요청 |

튜토리얼은 정규 60맵과 별 집계에서 제외합니다. EP01-01~03의 하트 면제는 독립 튜토리얼과 별도 규칙으로 표시했습니다. 에피소드명은 왕실의 부름 / 변덕쟁이 임금님 / 근위병 대소동 / 왕궁 무도회 / 이웃국가의 귀빈이며, ‘보이지 않는 옷’ 엔딩 화면은 포함하지 않았습니다.

## 편집과 검토 방법

UI의 글자·도형·아이콘은 Figma에서 편집할 수 있습니다. 버튼, 별 0~5개, 맵 카드, 주문 카드, 토글을 공통 컴포넌트로 구성했고 색상·간격 변수와 텍스트 스타일을 연결했습니다. 공방과 캐릭터만 A02 콘셉트 PNG를 사용합니다. PNG는 최종 3D 모델이나 애니메이션이 아닙니다.

기존 노드 3:3이 있는 페이지와 최신 통합 플로우 페이지에 새 UI 목차 바로가기를 추가했습니다. 각 화면 위의 제목과 회색 설명은 협업 메모로, 실제 게임 화면 밖에 배치했습니다. 오른쪽 검토 목차에서 모든 상태로 이동할 수 있습니다.

프로토타입에는 8개 시작점이 있습니다: 첫 실행, 이어하기, 시간 초과, 하트 0, 결과, 설정·계정, 오프라인, 백업 충돌. **목차 이동을 포함해 462개 연결**을 저장했습니다. 광고·로그인 대기 후 성공은 화면 전환으로 모의합니다. 맵별 실제 플레이와 서비스 기능을 실행하는 게임은 아닙니다.

각 프레임은 상태별 고정 예시입니다. 화면을 오가며 하트·코인이 실시간으로 누적되거나 모든 맵의 주문 데이터가 동적으로 바뀌지는 않습니다.

## v2.0 기준으로 맞춘 상태 예시

- 하트 최대 5개, 30분마다 1개 회복. 시작·성공 시 차감하지 않고 실패 확정 시 1개 차감합니다.
- 시간 연장은 한 판에 1회, +40초. 보유 모래시계 또는 선택형 광고 흐름을 구분했습니다.
- 첫 클리어 기본 100코인, 재도전 기본 25코인, 새로 얻은 별마다 20코인.
- 결과 광고는 기본 보상에만 50%를 추가합니다. 첫 3성 160→210코인, 재도전 2→4성 65→78코인 예시입니다.
- 1성과 5성은 광고 수령 후에도 각각 별·점수 상태를 유지합니다.
- 최고 별과 기본 보상을 저장한 뒤 추가 보상을 처리하는 상태를 구분했습니다.

## 검증한 범위

- UI 상태 111개와 검증 프레임 3개가 존재하는지 확인했습니다.
- 5개 에피소드명과 에피소드당 맵 카드 12개, 합계 60개를 대조했습니다.
- 462개 연결의 저장된 목적지를 다시 읽어 확인했고 누락은 없었습니다.
- 첫 실행→첫 클리어, 이어하기→결과, 시간 연장, 하트 회복, 별 등급별 광고 보너스, 로그인·저장 재시도 경로를 구조적으로 확인했습니다.
- 프레임 밖으로 나가는 텍스트 경계, 사용 글꼴, 이미지 영역과 UI 레이어 분리를 검사했습니다.
- 타이틀·맵·준비·플레이·연장·결과·하트·설정·계정 충돌 등 대표 레이아웃을 렌더링해 확인했습니다.
- 기본 960×540에 더해 대표 플레이의 19.5:9·20:9 배치와 영문 준비 화면을 확인했습니다.
- 버튼의 긴 문구, 보조 글자 대비, 결과 화면 하단 여백, 첫 클리어 후 별 표시를 보정했습니다.

이는 Figma 구조 및 대표 화면의 시각 검증입니다. Unity 실기기 조작, 모든 언어·기종·안전 영역, 실제 광고 SDK와 인증·클라우드 저장은 아직 검증하지 않았습니다.

## 개발 전에 결정할 항목

1. 맵별 점수 경계와 PAR: 300/420/540/660/780은 현재 예시입니다.
2. 아이템 가격: 화면의 80코인은 구매 UI 검토용 제안입니다.
3. 자발적 나가기·재시작 시 하트 처리와 중단 복구 범위.
4. 광고 한도·간격의 운영값과 실제 AppLovin MAX 콜백 처리.
5. 2차 계정 연동의 데이터 충돌·삭제 범위·처리 기간.
6. 에피소드별 최종 3D 공간·캐릭터 반응·동작 애니메이션.

다음 구현 단위는 독립 튜토리얼과 EP01-01의 제작·납품 루프입니다. 이 범위에서 조작·타이머·저장·결과를 먼저 연결한 뒤 EP01-02~03 및 광고·회복 예외로 확장합니다.
