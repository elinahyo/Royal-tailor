# A03 게임 경험 · 비주얼·사운드 구현 명세

기준일 2026-11-07. A02의 단순한 파스텔 로우폴리 아트는 유지하고, 게임의 행동–진행–완료–보상을 연결하는 피드백을 재설계한다. 기존 모바일 싱글플레이, 독립 튜토리얼, 5에피소드×12맵, 최대5성, 게스트/선택 로그인, AppLovin MAX 정책을 유지한다.

## 1. 문제 분석과 변경

| **기존 화면에서 부족했던 점** | **A03의 구체적 수정** |
|---|---|
| 메뉴와 설명 카드가 중심이어서 게임 세계가 뒤로 밀림 | 공방 전체 배경, 주문판·연습책 진입점, 원형 도구 버튼, 실로 이어진 12맵 지도 |
| 눌렀는지, 작업이 가능한지 불분명 | 70ms 눌림 / 110ms 복귀, 가까운 작업대 윤곽, 손에 든 원단·완성품 표시 |
| 제작 진행을 읽기 어려움 | 작업대 위 실 진행바, 재단·봉제 소리, 완료 체크와 다음 작업대 표시 |
| 납품의 결과와 별의 관계가 약함 | 납품 확인 → 칭찬 → 점수 이동 → 별 도달 → 결과 별 순차 등장 |
| 결과가 정적인 정보 목록처럼 보임 | 별3개 0.25/0.49/0.73초, 코인0.95초, 다음 목표1.6초 순서로 전달 |
| 로딩·오류·실패가 감정 흐름을 끊음 | 천 전환, 실제 준비 상태, 실패 이유와 다음 행동, 차분한 실패음 |
| 소리·진동·효과의 기준이 없음 | 이벤트별 큐·길이·우선순위·중단 조건, 효과 감소 대안, 사운드 견본 |

불만족이나 유지율 개선 수치는 아직 검증되지 않았다. 다음 플레이 테스트에서 행동 이해도와 재도전 의향을 확인한다.

## 3. 입력·제작·납품 이벤트 계약

| **이벤트** | **비주얼 / 시간** | **사운드 / 진동** | **실행 조건과 종료** |
|---|---|---|---|
| UI_PRESS | 70ms 깊이5→1px, 110ms 복귀 | ui_press 80ms / 선택 진동8ms | 활성 버튼에서만, 연타80ms 제한 |
| TARGET_ENTER | 가까운 작업대 외곽160ms 강조, 가능한 도구 표시 | 소리 없음 | 가장 가까운 유효 대상1개, 이탈 즉시 해제 |
| PICK_CONFIRMED | 원단120ms 확대·정착, 보유 슬롯 변경 | cloth_pick180ms / 10ms | 재료획득 확정 후1회, 실패하면 상태변경 없음 |
| CUT_STARTED | 작업대 위 실제 진행도, 가위 왕복 | cut150ms, 공정당 제한횟수 | 레시피 실제 소요시간에 비례, 프레임마다 호출 금지 |
| SEW_STARTED | 바늘 왕복·실 진행바 | sew_loop300ms 루프 | 작업 이탈·일시정지·광고·앱백그라운드 즉시 정지 |
| WORK_COMPLETED | 체크 + 250ms 튕김, 다음 목적지 | 낮은 완료음1회 / 12ms | 완료 이벤트ID 기준1회, 중복 콜백 무음 |
| DELIVERY_CONFIRMED | 칭찬0ms→점수250ms→HUD850ms, 작은 별7~9개 | deliver650ms / 18ms | 품목·색·공정 검증과 점수반영 후; 잘못된납품은 미소모 |
| MATERIAL_REJECTED | 원인+수정행동, 원단만160ms ±4px | 짧은 나무 톡 / 선택6ms | 붉은 전체화면·강한버저·자동재료삭제 금지 |
| STAR_RESULT | 별0.25/0.49/0.73초, 250ms 확대복귀 | star_1/2/3 각280ms / 첫·마지막 별만12ms | 획득등급만 채움, 새기록 배지는 최고기록 갱신 시만 |
| COIN_GRANTED | 0.95초 숫자확인→1.25~1.9초 지갑 이동 | coins500ms | 기본 보상 저장 성공 후1회, 시각 연출이 지급을 결정하지 않음 |
| MAP_UNLOCKED | 다음 노드200ms 튕김, 실 경로와 새주문 표식 | unlock620ms / 15ms | 이전맵1성이상 완료 확정 후, 새 게임 규칙을 한 문장으로 |
| TIME_WARNING | 10초 시계만 주황·짧은확대, 3/2/1초 표시 | warning100ms 최대4회 | 음악 전체 가속·반복 경보·화면점멸 없음 |
| TIMEOUT_PENDING | 시간·작업 정지, 250ms 후 연장 선택 | 작업루프 정지, 짧은 정지음 | 연장 선택 대기 중 하트 차감 없음 |
| FAIL_CONFIRMED | 이유·다음 행동·하트1개차감, 350ms 페이드 | fail600ms 두음 | 큰 실패 버저 없음, 최고별 유지 |
| REWARDED_SUCCESS | +40초 또는 +50코인 한 곳에 표시 | 목적별 짧은 수령음 | MAX 보상 콜백+중복방지 확인 후. 광고 닫기만으로 지급 안 함 |

공정 시간이 1.8초인 화면과 점수0→300→570은 연출 검토용 예시다. 실제 공정 시간과 점수는 레시피·맵 밸런스 데이터에서 공급한다. 연속납품으로 추가 점수를 주는 새 규칙은 도입하지 않았다.

## 4. 로딩과 전환

- 준비500ms 미만: 로딩 화면을 생략하고 180ms 전환.
- 준비500ms 이상: 실·천 모티브로 준비 상태 표시. 로딩 표시가 완료될 때까지 실제 준비 상태를 따른다.
- 3초 초과: “공방을 준비하고 있어요”와 현재 단계.
- 10초 초과 또는 오류: 재시도/공방 선택, 이미 저장한 진행 유지.
- 임의의 퍼센트나 강제 최소 대기시간을 넣지 않는다.
- 프로토타입의1.25초 로딩과1.2초 광고 대기는 검토용 성공 모의다.
- 카운트다운 총1.6초 뒤 타이머와 입력을 동시에 시작. 화면 전환 중 추가 하트 소모 없음.

## 5. 오디오·진동·효과 설정

- 따뜻한 나무·천 계열: 짧은 나무 클릭, 천 마찰, 가위, 가벼운 바느질. 과한 금속 충돌·카지노 코인폭발은 사용하지 않는다.
- BGM 견본은92BPM의 부드러운 플럭 계열. 최종 음악 편곡과 실제 Foley 녹음은 별도 제작한다.
- 믹스 제안: BGM 기본 -20dB, 작업 루프 -12dB, 중요 피드백 기준0dB. 납품·별 획득 때 BGM 추가 -5dB, 450ms 후 복귀.
- 우선순위: 보상/실패 확정 > 납품/시간 경고 > 조작/작업 루프 > 환경음. 동시 최대6보이스, 동일 큐는1개.
- 광고·앱백그라운드·일시정지에서 작업 루프 정지. 복귀 시 현재 공정만 재개하고 획득음을 다시 재생하지 않는다.
- BGM·효과음·진동을 각각 끌 수 있다. 음소거 상태에서도 원인·진행·완료·다음 목표를 글자와 아이콘으로 전달한다.
- 효과 줄이기: 동전 비행·확대·흔들림 제거, 120ms 이하 페이드와 즉시 상태 반영. 점수·별·금액·해금 조건은 동일하다.
- 진동은 지원 기기에서 설정 허용 시만 사용. 길이와 세기는 실기기에서 조정한다.

## 6. 보상과 기존 로직 유지

첫 클리어100코인 + 새별당20코인. 첫3성160코인, 선택 광고 기본보상의50%=50 추가 후210코인. 최고별을 낮추지 않는다. 하트최대5, 30분마다1회복, 실패 확정 시만1개차감. 독립튜토리얼과 EP01-01~03 면제를 구분한다. 튜토리얼 완료는 정규맵 별·코인을 지급하지 않는다.

계정·클라우드 충돌·광고 미충족·저장 실패 등 전체 서비스 조건은 기존 A02/v2.0 정의를 유지한다. A03은 주로 플레이 경험과 공통 피드백을 재설계한 버전이며, 계정 서비스 자체를 새로 구현한 것은 아니다.

A03 타이틀의 선택 로그인과 설정의 계정·백업 버튼은 기존 A02 로그인 프로토타입을 별도로 연다. 게임 경험의 대표 흐름은 A03 내부에서 이어지고, 변경하지 않은 서비스 예외는 기존 A02 목차에서 검토한다.

## 7. 구현·테스트 인계 기준

1. 버튼을 누른 뒤 반응 시작 목표100ms 이내. 실제 지연은 기기 측정으로 확인.
2. 재료 선택·작업 중·완료·잘못된납품·복귀를 소리 없이도 구분할 수 있는지 플레이 테스트.
3. 점수/코인/별을 먼저 확정하고 연출만 수행. 스킵·중복콜백·앱복귀로 재지급되지 않아야 함.
4. 중급 목표 기기60fps를 기준으로 이펙트8~12개 제한. 성능 저하 시 입자를 먼저 줄이고 글자·진행바 유지.
5. 사운드 켜기/끄기, 진동 끄기, 효과 줄이기 모두 같은 성공·실패 결과.
6. 10초 경고가 주문을 가리지 않는지, 실패 후 다음 행동을 설명할 수 있는지 관찰.
7. 최종3D 캐릭터 동작·기기 진동·실제 MAX와 저장 연동·실기기 성능은 아직 검증하지 않음.

모든 조절값은 구현 기준의 제안이며 실제 사용자 만족도·재방문 개선을 확정하는 근거가 아니다.
